从 KF 到 FAST-LIO2：机器人状态估计系列总结

这个系列从“传感器为什么不够可靠”开始，沿着 KF、EKF、ESKF 和 IEKF，一直写到了 FAST-LIO2。最后这篇不再引入新的滤波器，而是把前面的概念重新接起来，看看它们怎样一步步落到 LiDAR-IMU 状态估计里。

回头看这一串缩写，它们并不是互相替代的版本号。每往前一步，通常都是因为原来的问题多了一层：模型从线性变成非线性，状态里出现三维旋转，一次线性化不再够用，最后还要把 IMU、LiDAR 和地图维护放进同一个实时系统。

整条线可以压缩成一句话：

根据模型预测，用观测修正，再让不确定性决定这次修多少。

1. 状态估计一直在重复什么？

IMU、轮速计、LiDAR、相机都只能提供带噪声的局部信息。IMU 更新快，却会因为积分不断累积误差；LiDAR 能看到环境几何，但在长走廊、重复结构或退化场景里也可能缺少约束。状态估计器要做的，不是选出一个“绝对正确”的传感器，而是持续维护当前最合理的状态及其不确定性。

一轮估计通常包含三件事：

  1. 根据上一时刻状态和运动模型得到预测。
  2. 用新观测检查预测与现实之间的差异。
  3. 结合预测协方差和观测噪声，决定状态应当修正多少。

得到当前状态后，时间继续向前，下一轮又从这个结果开始。图中的闭环就是后面所有方法共同的骨架：

KF、EKF、ESKF 和 IEKF 的差别，主要发生在这个循环的内部：模型怎样写、状态怎样表示、线性化在哪里做，以及一帧观测到底更新几次。

2. KF：在线性高斯模型里完成预测和修正

标准卡尔曼滤波先给出了最干净的一版答案。以位置 \(p\) 和速度 \(v\) 组成的状态为例：

\[x_k = \begin{bmatrix} p_k \\ v_k \end{bmatrix}\]

线性状态模型和观测模型可以写成：

\[x_k = F_{k-1}x_{k-1} + B_{k-1}u_{k-1} + w_{k-1}\]
\[z_k = H_kx_k + v_k\]

其中 \(w_{k-1}\) 和 \(v_k\) 分别表示过程噪声与观测噪声。预测阶段同时传播状态和协方差：

\[\hat{x}_k^- = F_{k-1}\hat{x}_{k-1}^+ + B_{k-1}u_{k-1}\]
\[P_k^- = F_{k-1}P_{k-1}^+F_{k-1}^{T} + Q_{k-1}\]

观测到来后，先计算创新和创新协方差：

\[y_k = z_k - H_k\hat{x}_k^-\]
\[S_k = H_kP_k^-H_k^T + R_k\]

再由卡尔曼增益完成更新：

\[K_k = P_k^-H_k^TS_k^{-1}\]
\[\hat{x}_k^+ = \hat{x}_k^- + K_ky_k\]

这里最值得记住的不是矩阵位置，而是 \(Q\)、\(R\) 和 \(P\) 的含义。它们描述系统对运动模型、传感器和当前估计有多不确定，卡尔曼增益 \(K_k\) 则把这些不确定性换算成一次具体的修正权重。

标准 KF 的条件也很明确：状态转移和观测模型是线性的，噪声通常按零均值高斯噪声建模。机器人一旦转弯，或者观测里出现坐标变换和投影，这个条件很快就不再成立。

3. EKF：模型可以非线性，但更新仍靠局部近似

二维机器人按航向角 \(\theta\) 运动时，位置更新已经会出现：

\[p_{x,k} = p_{x,k-1} + v\Delta t\cos\theta\]
\[p_{y,k} = p_{y,k-1} + v\Delta t\sin\theta\]

这时状态模型和观测模型改写成非线性函数：

\[x_k = f(x_{k-1},u_k) + w_k\]
\[z_k = h(x_k) + v_k\]

EKF 直接用 \(f(\cdot)\) 预测状态，但在传播协方差和构造更新时，会在当前估计附近计算雅可比：

\[F_k = \left.\frac{\partial f}{\partial x}\right|_{\hat{x}_{k-1}^+}, \qquad H_k = \left.\frac{\partial h}{\partial x}\right|_{\hat{x}_k^-}\]

雅可比可以看成一种局部灵敏度：状态在这里动一点，预测或残差会跟着动多少。它只保证当前估计附近的近似，所以初值离真值太远、模型弯曲明显时，一次线性化可能会留下较大误差。

从图里能看到，EKF 没有推翻 KF 的预测与修正框架。它只是把线性模型换成了非线性模型，再用雅可比把不确定性传播和观测更新接回卡尔曼滤波。

4. ESKF：滤波器估计的是“当前错了多少”

EKF 能处理非线性，但三维姿态还带着额外的几何约束。位置和速度可以直接相加，旋转矩阵却不能随意写成 \(R+\delta R\)，否则结果未必仍是合法旋转。

ESKF 把状态分为两部分：

  • 名义状态 \(x\)：由非线性模型正常传播，保存当前姿态、位置、速度等估计。
  • 误差状态 \(\delta x\)：描述真实状态与名义状态之间的小偏差，由滤波器估计。

两者通过流形上的加法连接：

\[x_{\mathrm{true}} = x \boxplus \delta x\]

在常见的惯性状态里，误差状态可包含：

\[\delta x = \begin{bmatrix} \delta\theta & \delta p & \delta v & \delta b_g & \delta b_a & \delta g \end{bmatrix}^{T}\]

位置、速度和零偏等欧氏量可以直接注入：

\[p \leftarrow p + \delta p,\qquad v \leftarrow v + \delta v,\qquad b \leftarrow b + \delta b\]

姿态则通过小角度扰动更新。采用右扰动约定时，可写成：

\[R \leftarrow R\,\mathrm{Exp}\!\left([\delta\theta]_\times\right)\]

左扰动与右扰动都能使用，但误差定义、雅可比和注入公式必须保持同一套约定，不能在推导中混用。

误差注入后，误差状态会重新置于零附近，协方差也要按照误差重置关系做相应变换。这个“注入并重置”的步骤，是 ESKF 不应被简化成普通向量加法的地方。

ESKF 仍然属于 EKF 框架。它不是另一套与 EKF 无关的滤波器，而是一种更适合姿态、IMU 和流形状态的组织方式。

5. IEKF：同一帧观测里重新线性化

普通 EKF 通常围绕预测状态线性化一次，然后完成一次观测更新。LiDAR scan-to-map 这类几何观测对位姿很敏感：位姿改变后，点云在地图中的投影会变，残差和雅可比也应在新状态附近重新计算；一些实现还会按需要刷新邻近点与局部平面。

IEKF 的迭代发生在同一帧观测更新内部。一次迭代大致会：

  1. 在当前迭代状态处计算预测观测、残差和雅可比。
  2. 求出本轮状态增量并更新当前迭代状态。
  3. 检查增量或代价是否已经收敛。
  4. 未收敛时，在新状态附近重新线性化。

达到收敛条件或最大迭代次数后，才输出这一帧的更新状态。

这不是把整套滤波器从预测阶段重新跑几遍，也不会在每次迭代里读取一帧新数据。它只是反复改进同一帧观测对应的局部近似。

ESKF 和 IEKF 解决的是两个不同维度的问题：前者关心状态及误差怎样表达，后者关心一次观测更新要不要迭代。把误差状态表达、流形注入和迭代线性化放在一起，通常就称为 IESKF。严格实现还涉及先验项、协方差处理、扰动约定和收敛判据，所以它不只是“给 ESKF 外面套一个循环”。

6. FAST-LIO2：这些概念怎样落到系统里

FAST-LIO2 是 LiDAR-IMU 紧耦合里程计与建图系统，不是单独一个卡尔曼滤波器。滤波只是其中的状态估计核心，外围还包括时间同步、IMU 初始化、点云去畸变、地图搜索、残差构建和增量建图。

常见状态包含姿态 \(R\)、位置 \(p\)、速度 \(v\)、陀螺仪零偏 \(b_g\)、加速度计零偏 \(b_a\)、重力 \(g\)，以及按配置决定是否估计的 LiDAR-IMU 外参。IMU 在两帧 LiDAR 之间高频传播状态和协方差；LiDAR 到来后，系统使用地图几何残差纠正这份预测。

图里的链路可以分成四段看：IMU 预测、点云处理、scan-to-map 观测更新、地图增量维护。它们共享同一份状态，因此不能只盯着滤波公式而忽略前后的数据流。

6.1 IMU 传播与点云去畸变

IMU 测得角速度和比力。扣除零偏后，系统积分姿态、速度和位置，同时传播误差协方差。它能在 LiDAR 帧之间提供连续、高频的运动估计，但积分误差会随时间累积，因此只能作为短期预测。

一帧 LiDAR 点云也不是在同一瞬间采完的。扫描期间机器人持续运动，不同点对应不同采样时刻。FAST-LIO2 利用扫描期间的 IMU 运动轨迹，把这些点补偿到统一参考时刻，否则墙面和平面可能被运动拉弯。这就是点云去畸变。

6.2 LiDAR 怎样形成观测

去畸变后的当前帧点云会按预测位姿变换到地图坐标系。暂时省略 LiDAR-IMU 外参，对当前点 \(p_i\) 可写成：

\[p_i^w = Rp_i + t\]

系统在地图中搜索 \(p_i^w\) 的邻近点并拟合局部平面。若平面法向量为 \(n_i\)，平面上一点为 \(q_i\)，点到平面残差可写成：

\[r_i = n_i^T\left(Rp_i+t-q_i\right)\]

残差并不直接给出一个绝对位姿，它只说明当前状态能否让点云与地图局部平面对齐。大量点的残差和雅可比共同构成 LiDAR 观测，IESKF 再据此修正姿态、位置、速度和零偏等状态。

6.3 为什么状态更新后才能更新地图

当前点云既是这一帧的观测来源，也会成为后续帧使用的地图数据。若位姿还没修正就把点云插进地图，墙面会重影、平面会变厚，下一帧的对应关系也会被污染。

因此顺序应当是：先用当前帧对地图构造残差并收敛状态，再用更新后的位姿变换点云，最后筛选并插入 ikd-Tree。ikd-Tree 提供邻近点查询、增量插入和局部地图维护，让这条闭环能够实时运行。

7. 各种方法不是一条“升级榜”

前面的主线容易让人误以为缩写越长，算法就越高级。实际选择取决于问题本身：

  • 线性高斯系统可直接使用 KF。
  • 一般非线性系统可考虑 EKF、UKF 或 CKF。
  • 含姿态和 IMU 的连续状态估计常采用误差状态表达。
  • 强非线性观测可能需要在同一帧内迭代线性化。
  • 多峰分布、全局定位和重定位更适合粒子滤波一类多假设方法。

这张图适合用来找大方向，不应当当成严格的一一对应表。例如 ESKF 也要处理非线性，IESKF 本身也建立在扩展卡尔曼滤波的线性化框架上；UKF、CKF 与粒子滤波则是处理非线性和概率分布的其他路线，并非 KF 到 FAST-LIO2 的必经步骤。

8. 几个容易混在一起的概念

ESKF 与 EKF

ESKF 仍是 EKF。区别在于它围绕名义状态建立小误差模型，并通过流形注入更新姿态等状态。滤波器主要估计 \(\delta x\)，不等于系统只维护误差而不维护完整状态。

IEKF 与 IESKF

IEKF 强调同一帧观测内的重复线性化；IESKF 同时采用误差状态表达与迭代更新。这里的 IEKF 指 Iterated Extended Kalman Filter，不要与文献中的 Invariant Extended Kalman Filter 混淆，后者有时也使用 IEKF 这个缩写。

FAST-LIO2 与 IESKF

IESKF 是 FAST-LIO2 的状态更新框架之一，FAST-LIO2 还包含 IMU 预处理、去畸变、点云筛选、地图匹配和 ikd-Tree 维护。只读滤波更新函数，仍看不完整个系统。

紧耦合与松耦合

松耦合通常先让各传感器独立产生位姿或速度结果，再融合这些结果。紧耦合把 LiDAR 的原始几何残差直接送入统一状态估计框架。FAST-LIO2 使用点到平面残差直接修正状态，更接近后者。

9. 读 FAST-LIO2 代码时可以抓哪些线索

以后再看论文或代码时，可以先找下面几条线，不必一上来就从某个大矩阵开始硬啃：

  • 状态传播：IMU 如何更新 \(R,p,v\) 和协方差。
  • 点云去畸变：每个点怎样根据采样时刻补偿运动。
  • 地图观测：点怎样变换到地图、搜索邻近点并拟合平面。
  • 残差与雅可比：当前状态改变时，点到平面距离怎样变化。
  • 迭代与收敛：同一帧观测在哪里重复线性化，何时停止。
  • 误差注入：\(\delta\theta,\delta p,\delta v,\delta b\) 怎样写回名义状态。
  • 地图更新：什么时候筛选并插入当前点云，局部地图怎样维护。

这些模块按数据流连起来以后，FAST-LIO2 就不再是一组彼此孤立的类和函数。

10. 把整条路线放回一张图

从 KF 走到 FAST-LIO2，变化的并不是“预测与修正”这件事，而是问题的数学结构和工程规模：

  • KF 给出线性高斯系统里的递推估计。
  • EKF 用局部线性化处理非线性模型。
  • ESKF 用名义状态和误差状态处理姿态与惯性状态。
  • IEKF 在同一帧观测里反复线性化，减小单次局部近似带来的偏差。
  • IESKF 把误差状态表达与迭代更新结合起来。
  • FAST-LIO2 再把这套估计框架接到 IMU、LiDAR 几何残差和增量地图上。

横向看的 UKF、CKF 和粒子滤波没有被塞进这条纵向路线，因为它们走的是不同的近似或概率表示方法。它们同样重要，只是回答的不是“FAST-LIO2 为什么会沿这条线演化”这个问题。

11. 写完这一组笔记后留下的记法

公式以后可能还会忘，但下面几层关系值得留住：

  1. 状态估计维护的不只是一个数值，还包括对这个数值有多不确定。
  2. KF 的骨架是预测、观测修正和协方差传播。
  3. EKF 没有消除非线性，只是在当前估计附近进行一阶近似。
  4. ESKF 估计名义状态的局部误差，并把误差按状态的几何结构注入回去。
  5. IEKF 的迭代属于同一帧观测更新，不是重复读取数据或重跑整段系统。
  6. FAST-LIO2 用 IMU 提供连续预测和去畸变，用 LiDAR 地图几何残差约束漂移，再用更新后的状态维护地图。

整套系统最终仍在重复最早的那件事：模型先给出一个带不确定性的预测，传感器再用现实把它拉回来。后面的数学越来越复杂，是因为机器人状态、观测和地图都越来越接近真实世界，而不是因为“预测—修正”这条主线变了。
